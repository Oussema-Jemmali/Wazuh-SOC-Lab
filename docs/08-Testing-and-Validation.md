# Testing and Validation

## Overview

Testing was performed to validate the functionality of the SOC laboratory components and verify the integration between network infrastructure, high availability services, and the Wazuh SIEM platform.

The main objectives were:

- Verify HAProxy load balancing functionality.
- Confirm automatic failover when a web server becomes unavailable.
- Verify communication between the Wazuh agent and Wazuh server.
- Validate pfSense Syslog forwarding to Wazuh.
- Confirm that Wazuh custom rules detect HAProxy availability events.

---

# Test Environment

The validation was performed using the following components:

- pfSense firewall with HAProxy.
- Apache1 web server with Wazuh agent.
- Apache2 web server.
- Wazuh Server (SIEM).

# Test 2: Apache1 Failure Simulation and HAProxy Failover

## Objective

Verify that HAProxy maintains service availability when Apache1 becomes unavailable.

## Procedure

1. Confirmed that Apache1 and Apache2 were running.
2. Accessed the web service through HAProxy.
3. Stopped the Apache service on Apache1.

Command used:

```bash
sudo systemctl stop apache2
```

4. Checked HAProxy backend health status.
5. Accessed the service again through HAProxy.

## Expected Result

HAProxy should detect Apache1 failure and redirect traffic to Apache2 automatically.

## Result

After stopping Apache1:

- HAProxy marked Apache1 as unavailable.
- Apache2 remained available.
- The web service continued working successfully.

**Status: PASS**

## Failover Flow

Before failure:

```
                HAProxy

                   |
        ______________________
       |                      |
       v                      v
    Apache1                Apache2
      UP                     UP
```

After Apache1 failure:

```
                HAProxy

                   |
                   |
                   v

                Apache2
                  UP
```

The test confirmed that HAProxy provides automatic failover and maintains service availability.

# Test 4: pfSense HAProxy Logs Integration with Wazuh SIEM

## Objective

Verify that HAProxy events generated by pfSense are collected and analyzed by Wazuh.

## Procedure

1. Enabled HAProxy logging on pfSense.
2. Configured pfSense to forward Syslog messages to the Wazuh Server.

Configuration:

| Setting | Value |
|---------|-------|
| Remote Syslog Host | 192.168.1.100 |
| Protocol | UDP |
| Port | 514 |
| Facility | local0 |
| Level | info |

3. Configured the Wazuh Manager Syslog receiver:

```xml
<remote>
    <connection>syslog</connection>
    <port>514</port>
    <protocol>udp</protocol>
    <allowed-ips>192.168.1.0/24</allowed-ips>
</remote>
```

4. Generated HAProxy events by stopping and starting Apache services.
5. Verified Syslog traffic using tcpdump.

Command used:

```bash
sudo tcpdump -i any -A udp port 514
```

## Expected Result

Wazuh should receive HAProxy events generated by pfSense.

## Result

HAProxy events were successfully received by Wazuh.

Example:

```
haproxy:
Server agil_web_servers_ipvANY/apache_vm1 is DOWN,
reason: Layer4 connection problem
```

**Status: PASS**

# Test 5: Wazuh Custom Detection Rules

## Objective

Verify that Wazuh custom rules generate alerts from HAProxy events.

## Procedure

1. Created custom Wazuh rules for HAProxy events.
2. Restarted the Wazuh Manager.
3. Simulated Apache backend failures and recoveries.
4. Checked the Wazuh Dashboard alerts.

## Detection Rules

### Apache1 Backend Failure

Rule ID:

```
100100
```

Detection:

```
Server agil_web_servers_ipvANY/apache_vm1 is DOWN
```

Action:

Generate an alert indicating Apache1 failure and HAProxy failover.

---

### Apache1 Recovery

Rule ID:

```
100101
```

Detection:

```
Server agil_web_servers_ipvANY/apache_vm1 is UP
```

Action:

Generate an alert indicating Apache1 recovery.

## Result

Wazuh successfully generated alerts in the Dashboard.

The alerts displayed:

- HAProxy event source.
- Backend server status.
- Custom rule ID.
- Event description.

**Status: PASS**
